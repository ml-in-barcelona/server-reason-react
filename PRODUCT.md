# Product

## Register

product

## Users

React and OCaml library maintainers, contributors, and evaluators using the demos to understand and validate server rendering, Server Components, and router behavior.

## Product Purpose

Provide executable examples that make server-reason-react capabilities observable and trustworthy. Success means an evaluator can exercise a feature, understand its behavior, and use the implementation and documentation as a reliable integration reference.

## Brand Personality

Technical, restrained, dependable.

## Anti-references

Do not turn technical demos into marketing pages, decorative showcases, or novel UI experiments. Avoid visual changes that obscure the behavior being demonstrated or introduce affordances inconsistent with the existing demo.

## Design Principles

- Make the demonstrated behavior obvious and directly testable.
- Preserve familiar controls and interaction patterns so the library behavior remains the focus.
- Keep UI state, URL state, and rendered output visibly consistent.
- Prefer small, durable examples over presentation-specific abstractions.
- Treat accessibility and predictable keyboard behavior as part of correctness.

## Accessibility & Inclusion

Target WCAG AA contrast and interaction behavior. Preserve keyboard access, visible labels, and reduced-motion preferences. Functional fixes must not rely on color or motion alone.
