Request data

Sourceval request : unit -> Dream.request option

The request being handled. routes, createFromRequest and streamFunctionResponse hold it for the whole response, including streaming, so route loaders, ~metadata, ~headers, server components and server functions read their own request after any Lwt wait, also when requests run concurrently. None outside a request. routes and createFromRequest also open RouterServer.requestScope around the response; a server function runs outside it.

Sourceval get_header : string -> string option

Read a request header from the ambient request.

Available in server components and server functions. Raises outside a request context.

  • parameter name

    case-insensitive header name

Sourceval get_cookie : ?decrypt:bool -> string -> string option

Read a cookie from the ambient request.

Available in server components and server functions. Raises outside a request context.

  • parameter decrypt

    whether to decrypt the cookie value (default: false)

  • parameter name

    cookie name

Streaming

Sourceval createFromRequest : ?debug:bool -> ?disableSSR:bool -> ?layout:(React.element -> React.element) -> ?bootstrapModules:string list -> ?bootstrapScripts:string list -> ?bootstrapScriptContent:string -> React.element -> Dream.request -> Dream.response Lwt.t

Render a React element as a full HTML page or RSC model stream, depending on the request's Accept header.

Installs a render-phase request context: get_header and get_cookie are available, while set_cookie raises.

  • parameter debug

    enable RSC and HTML stream logging (default: false)

  • parameter disableSSR

    stream only the document shell before client rendering (default: false)

  • parameter layout

    wrap the supplied element in a document or application shell

  • parameter bootstrapModules

    JavaScript modules loaded by the HTML response

  • parameter bootstrapScripts

    classic JavaScript files loaded by the HTML response

  • parameter bootstrapScriptContent

    inline bootstrap JavaScript

  • parameter element

    React tree to render

  • parameter request

    current Dream request

Sourceval streamFunctionResponse : ?debug:bool -> ?timeout:float -> lookup:(string -> ReactServerDOM.server_function option) -> Dream.request -> Dream.response Lwt.t

Handle a server function POST request.

Installs an action-phase request context in which get_header, get_cookie, and set_cookie are available. Pending cookies are serialized as Set-Cookie response headers. If the action raises, pending cookies are discarded. If it calls RouterServer.redirect, the response keeps its cookies, carries Router-Redirect: <href> and the result null.

  • parameter debug

    enable action-response logging (default: false)

  • parameter timeout

    maximum action execution and response streaming time in seconds (default: 30)

  • parameter lookup

    maps an action ID to a registered ReactServerDOM.server_function

  • parameter request

    current Dream request

Sourceval routes : server:(React.element, 'error, 'context) RouterServer.t -> context:(Dream.request -> 'context) -> actionHandler:(Dream.request -> Dream.response Lwt.t) -> ?lookup:(string -> ReactServerDOM.server_function option) -> ?diagnosticId:(exn -> string) -> ?revision:(unit -> string) -> ?ssr:(Dream.request -> bool) -> ?bootstrapModules:string list -> ?pageCacheCapacity:int -> document:(head:React.element -> React.element -> React.element) -> unit -> Dream.route list

Register document, RSC, and server-function routes for a generated router.

GET and HEAD run the router; a HEAD response has the same status and headers and no body. POST goes to actionHandler behind Dream.origin_referrer_check: a POST whose Origin (or Referer) does not match Host answers 400. An RSC request with Router-Prefetch: <level> is a prefetch at that level (see RouterEngine.ServerEngine.run); a value that is not a level is ignored. OPTIONS answers 204 and any other method answers 405, both with Allow: GET, HEAD, OPTIONS, POST.

  • parameter server

    generated router server

  • parameter context

    builds the request context once per routed request, inside the request context of request. Loaders, ~metadata and ~headers receive it as ~context. Pass fun _ -> () for a manifest without ~context

  • parameter actionHandler

    server-function POST handler

  • parameter lookup

    maps an action ID to a registered ReactServerDOM.server_function. With it, a page form posted without JavaScript (multipart, no ACTION_ID header) runs its server function here and answers 303 to the page, 303 to the destination given to RouterServer.redirect, or the page rendered with its nearest error boundary when the function fails (see RouterServer.formActionReply). Cookies set by a failed function are dropped. Other POSTs go to actionHandler. Without it, every POST goes to actionHandler

  • parameter diagnosticId

    produce a safe identifier for an internal exception (default: 12 random bytes from Dream.random, base64url)

  • parameter revision

    produce the revision attached to a successful response (default: as diagnosticId)

  • parameter ssr

    decide whether to include the routed root markup in each document response (default: always true). An empty hidden div#ssr-query-param marker renders next to the root markup, so the bootstrap module can check the DOM for it: present means mount with ReactDOM.Client.hydrateRoot, absent means ReactDOM.Client.createRoot

  • parameter bootstrapModules

    JavaScript modules loaded by document responses

  • parameter pageCacheCapacity

    maximum visited pages cached by the client router (default: the client's 30; 0 turns it off)

  • parameter document

    build the HTML document. ~head is the resolved metadata, to place inside <head>.
